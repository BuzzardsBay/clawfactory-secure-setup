## 1. PART A — the fix (DONE, verified in isolation)

The `cfv-0716w` close-out proved v1.0.39's ownership fix works but RED-gated on a
regression in that same fix: Task 3 removed `|| true` from three belt-and-suspenders
`systemctl --user` calls, so under `set -e`+`pipefail` a benign non-zero aborted the
install after the unit was created.

**Fix (setup.ps1 `$gatewayInstall`, v1.0.40):**
```
-echo "[gateway-install] systemctl --user daemon-reload"
-systemctl --user daemon-reload 2>&1 | tee -a "$LOG"
+XDG=/run/user/$(id -u clawuser 2>/dev/null || echo 1000)
+echo "[gateway-install] systemctl --user daemon-reload"
+XDG_RUNTIME_DIR="$XDG" systemctl --user daemon-reload 2>&1 | tee -a "$LOG" || true
   (same for enable + restart)
```
- Restores tolerance two ways: a real user bus (`XDG_RUNTIME_DIR`) **and** `|| true` as the
  safety net regardless — the `/status` poll (untouched) is the health authority.
- The **unit-existence hard gate and the ownership fix are untouched** (proven working).
- The throw message now distinguishes exit 90 (ownership guard) from a missing unit;
  systemctl can no longer reach a fatal throw.
- The three calls still `tee` to install.log (A3 — which/if any fails, on record).

**Verified in isolation** (local `bash`, since the VM never reached this code):
```
with `|| true`  (v1.0.40): a failing piped systemctl -> block completes, rc=0
without `|| true` (v1.0.39): a failing piped systemctl -> block ABORTS, rc=1   (the cfv-0716w bug reproduced)
```
`bash -n` clean. This is the exact behavioural difference that fixes the regression.

## 2. PART B — BLOCKED at the install gate (verbatim)

The install "finished" in ~3 min with `INSTALLER_EXIT=1` and **no honest marker** — the
v1.0.40 Task-4 honest-signal fix correctly flagged this ("NO INSTALLER_DONE marker …
setup.exe exit is not authoritative"), which led straight to the Inno log:

```
2026-07-16 17:12:57  Setup command line: ... /SILENT ... /PROVIDER=claude /LICENSE=CF-TEST-TEST-TEST-TEST
2026-07-16 17:13:02  License activation failed under /SILENT - missing or invalid /LICENSE= argument.
2026-07-16 17:13:02  InitializeWizard raised an exception (fatal).
2026-07-16 17:13:02  Got EAbort exception.
2026-07-16 17:13:02  Deinitializing Setup.
```

**The `/LICENSE=CF-TEST-TEST-TEST-TEST` argument is present** — so this is not "missing", it
is **"invalid": the activation call was rejected.** `InitializeWizard` is Inno's **first**
code step, before setup.ps1 runs, so:
- setup.ps1 never executed → no WSL distro imported → the probe's `WSL_E_DISTRO_NOT_FOUND`
  was a **symptom**, not the cause;
- no `C:\ProgramData\ClawFactory\install.log` (setup.ps1 never logged);
- **the gateway step was never reached — v1.0.40's fix is neither confirmed nor refuted.**

**Why this is environmental, not a v1.0.40 defect:** the identical `/LICENSE=…` line
**activated successfully on cfv-0716w ~3 h earlier** (that install ran 20 min and reached
the gateway step). v1.0.40 changed only the gateway systemctl block (deep in setup.ps1,
never reached) and the version number; the `.iss [Code]` license logic is unchanged. So the
**live activation API is now rejecting `CF-TEST-TEST-TEST-TEST`** where it accepted it
earlier today.
