## The new root cause + recommended fix (follow-up; NOT fixed here — out of scope, no PART A)
`clawfactory-turn-gate.sh:54`: `usage=$(openclaw gateway usage-cost --json --days 400 2>/dev/null)`;
empty ⇒ `spend_meter_unknown` block. When the gateway is cold, the 400-day JSON query returns empty,
so the first turns after install are fail-safe-blocked. This is the SINGLE root behind: the 4.2
cold-blank (cfv-0717d), the T6.1/T6.2 blank (cfv-0717d), and this run's 4.2 block.

Fix directions (a small installer/turn-gate change, its own job):
1. **Prime the meter at the end of install** — one `openclaw gateway usage-cost --json --days 400`
   call so the WS is hot before the first customer turn.
2. **Make the turn-gate meter read robust** — retry the `usage-cost` read a few times (or with a
   generous timeout) before declaring `spend_meter_unknown`; and/or use a smaller `--days` window
   matching the governor period (faster to return when cold). Keep the fail-safe.

The fail-safe itself (`unknown ⇒ block`) is CORRECT and must stay; the fix is to make the meter
readable in time, not to weaken the gate.
