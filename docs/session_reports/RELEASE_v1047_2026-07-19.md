### A2 — interop hardening (Finding A) — dependency check FIRST

`setup.ps1`'s wsl.conf now writes:
```
[interop]
enabled=false
appendWindowsPath=false
```
alongside `[automount] enabled=false`, so file isolation is no longer transitive on
`automount=false` alone.

**Dependency finding (A2.1–2.3): nothing depends on WSL→Windows interop — safe to apply.**
Searched `setup.ps1`, every `resources/*` (scripts + the `.sh` runtime set), `smoke-test.ps1`,
and `adversarial-suite.ps1`. Every Windows-binary invocation is **Windows→WSL** (Windows
PowerShell/VBScript calling `wsl.exe`, `powershell.exe`, `cmd.exe`, `cmdkey.exe`), which
`interop.enabled` does **not** govern:
- The **grant path** calls `wsl.exe -u root` **from Windows** (`clawfactory-grants.ps1`); it
  does not use in-WSL interop. Confirmed live: the drvfs grant mount was present and the agent
  read through it (B5).
- The **launcher/replay** runs as the Windows end-user; the **kill switch** is Windows-side; the
  **keepalive** (`wsl-keepalive.vbs`) runs `wsl.exe … sleep infinity` from Windows.
- **ClawChat→gateway** is loopback networking (WSL2 localhost forwarding), not interop —
  unaffected, and Tier 6 proxy checks all pass.
- All `/mnt/c` references in the harnesses are **negative-control targets** (expected
  unreachable, governed by automount), not dependencies.

Verified on the box (B4): `powershell.exe`/`cmd.exe` return `command not found` (rc=127), and
the agent PATH carries no `/mnt/c` entries. Expected side benefit confirmed — the
PATH-translation stderr noise that plagued earlier probes is gone.

**Guard precision preserved.** Adding `[interop] enabled=false` would have let a bare
`grep enabled=false` pass even if automount alone drifted to `true`, silently weakening the
P0 file-isolation guard. So `Assert-WslAutomountDisabled` and the "WSL automount disabled"
smoke check were made **section-aware** (scoped to the `[automount]` block). Tested against
four wsl.conf variants before shipping; the mid-probe smoke ("WSL automount disabled") passed
on both runs.

### A3 — safety-rules (SOUL) reword

`resources/safety-rules.md`, per the audit's R1/R2, so the agent-recited SOUL no longer states
the gateway-path gate as absolute — **without naming any bypass**, and keeping the
file-integrity sentence strong:
- **R1 (L18):** "Every turn is gated in code before you start: a spend cap and a SOUL integrity
  check. A blocked turn never runs." → "**Turns are gated in code before you start** — a spend
  cap and a SOUL integrity check — **and you must not attempt to run outside that gate**. A
  gated turn that is blocked does not run."
- **R2 (L5):** "re-checked in code before **every turn**" → "re-checked in code **before a gated
  turn runs**"; the "root-owned, read-only, and immutable — your account cannot change it"
  sentence kept verbatim.

The SOUL hash pin is computed at install (`Get-FileHash` in `Step-ApplySafetyRules`; `sha256sum`
in `freeze-injected-soul.sh`) — no hardcoded factory hash to update. Verified: on cfv-0719b the
agent recited the new wording verbatim (B6/7.4) and both pins matched after install.

## Known residuals (unchanged; none new, none blocking)

- **Door-2 full-path `.mjs` bypass** (adversarial T5.2, `bypassed=True`) — the accepted,
  documented v1 residual (Fable Path B; `SECURITY_FINDINGS.md`; backlog #25). Expected.
- **DNS via the allowed resolver still forwards** (T1.1j) — reduction, not elimination;
  known-open by design.
- **T5.1 "chatCompletions route ungated"** — a *stale* adversarial-suite NOTE that predates the
  gating proxy; it probes the raw route, but ClawChat's path is now gated by the root proxy
  (Tier 6 all PASS, T6.5 proves `clawuser` cannot reach the private 8788). Superseded, not new.
- **Trailing default-suite smoke 18/19** on "Gateway responds 200" (both runs) — a **post-probe
  transient**: the default `azure-probe.ps1` suite runs immediately after the payload probe,
  which stops/restarts the gateway (Task 8) and tampers/restores the SOUL (Task 11); every
  in-probe gateway check (2.3, 3.3 post-5-min-idle, 3.5) was 200. Attributed to probe churn, not
  a clean-install defect. Candidate future tidy: settle the gateway before the trailing suite, or
  `-SkipSuite` when the payload probe already covers the install gate.
