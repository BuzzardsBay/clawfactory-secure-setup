## TASK 1 — Diagnosis and mechanism

### Where the boundary is (VERIFIED)
```
(a) fresh 'wsl -u clawuser' shell   mnt ns: mnt:[4026532295]
(b) gateway process (pid 2498)      mnt ns: mnt:[4026532219]
    systemd --user manager (pid 233) mnt ns: mnt:[4026532219]   <- gateway inherits this
    gateway PPID chain: 2498 -> 233 (systemd --user) -> 1 (systemd)
root '/' propagation: private
```
The gateway (and every agent it runs) live in the **systemd --user manager's** mount namespace `[4026532219]`, cloned at boot. A fresh `wsl` invocation gets a *different* namespace `[4026532295]`. Root `/` is **private**, so a mount made in one namespace does not propagate to the other. The grant engine mounted via `wsl -u root -- mount` (a fresh-wsl namespace) → invisible to the agent.

### What creates the boundary (VERIFIED)
The gateway's systemd unit does **not** isolate mounts:
```
systemctl --user cat openclaw-gateway.service
[Service]
ExecStart=/usr/bin/node /usr/lib/node_modules/openclaw/dist/index.js gateway --port 8787
```
No `MountFlags`/`PrivateMounts`/`ProtectHome`. The split is simply that WSL gives the systemd --user session and fresh `wsl` invocations **independent private mount namespaces**; with `/` private there is no propagation between them.

### Propagation is NOT the answer (VERIFIED by test)
Mount-propagation events only flow between namespaces that shared the mount as a peer when they diverged. The gateway namespace diverged at boot with `/` private, so a `mount --make-shared` now cannot retroactively push a new mount into it. Direct test — a plain mount in the fresh-wsl ns is invisible in the gateway ns:
```
1) plain mount in fresh-wsl ns -> gateway ns check
   this-ns sees:    hello.txt
   gateway-ns sees:            (empty)
```

### Chosen mechanism: `nsenter` into the gateway's namespace (VERIFIED)
Mount the granted folder **inside the gateway's mount namespace** via `nsenter -t <gateway-pid> -m -- mount …`. Direct test:
```
2) nsenter mount INTO the gateway ns
   gateway-ns sees: hello.txt
   gateway-ns read: nsenter-seed-content
   this-(fresh)-ns sees:            (empty)   <- mount scoped to the gateway ns only
```
And it adds **only** the granted folder — nothing else:
```
3) isolation check: /mnt/c visible in the gateway ns?
   gateway-ns /mnt/c: $Recycle.Bin AMD Config.Msi ...   <- ONLY because automount=true (drift); the fix does not add this
```

**Rejected alternatives:**
- **Shared mount propagation (my 1st preference):** rejected — the gateway namespace already exists as a private clone; `/` is `private`, so a new shared mount cannot propagate into it retroactively (VERIFIED: plain mount invisible in gateway ns).
- **Change how the agent is spawned to inherit a namespace:** rejected — it would require touching OpenClaw's gateway/agent spawn, which is out of bounds, and the gateway namespace is exactly the one we can target from outside.
- **Disable systemd isolation / enable automount / mount /mnt/c / run agent outside the sandbox:** explicitly rejected — each trades away the product's isolation.

`nsenter` costs one moving part: the engine must know the gateway PID and re-apply after a full restart (new namespace). Handled by replay (Task 2). No gateway restart is needed to apply a grant while the gateway is already running (the normal case).

## TASK 2 — Implementation

`resources/clawfactory-grants.ps1`: a shared preamble resolves the gateway pid and defines `gwns` = run-in-gateway-namespace; `Grant-Workspace`, `Revoke-Workspace`, `Test-WslMountLive`, `Invoke-GrantReplay`, and `Invoke-GrantKillUnmount` now do all mount/umount/mountpoint work via `gwns` (i.e. `nsenter -t <gwpid> -m`). `Invoke-GrantReplay` first **waits up to 30 s** for the gateway process (the launcher fires Start-Gateway asynchronously), then re-mounts into the *current* gateway namespace. Grant while the gateway is down records the grant and defers the mount to replay.

**Replay after a gateway service restart — mount survives** (the namespace belongs to the persistent systemd --user manager, not the gateway process). AGENT-verified:
```
mount survived the gateway restart (same systemd --user ns): True
replay: replayed=0 alreadyMounted=1 broken=0
agent said: Exact contents of .../replay-marker.txt: ``` REPLAY-MARKER-42 ```
RESULT: 3 pass, 0 fail
```
**Replay after a full `wsl --shutdown` — mount lost, replay re-establishes it** (new namespaces). AGENT-verified:
```
PASS  mount live before shutdown
PASS  mount GONE after wsl --shutdown (new ns)
replay: replayed=1 alreadyMounted=0 broken=0
PASS  mount live after replay
PASS  agent reads marker after wsl --shutdown + replay        (agent printed SHUTDOWN-MARKER-99)
restore state: http=200
RESULT: 4 pass, 0 fail
```
(The `ClawFactory WSL Host` keepalive task was re-triggered and the gateway confirmed 200 afterward — Phase 1 finding, ground rule 4.)

## SURPRISES

1. **The mount survives a gateway *service* restart but not a `wsl --shutdown`.** The nsenter target namespace belongs to the systemd --user *manager* (pid 233), which outlives gateway restarts. So replay is a no-op after `systemctl --user restart` (mount still live) and only re-mounts after a full WSL restart. Good: fewer windows where the agent is blind.
2. **The demo agent recognised its own prior output** ("summary.md is already saved and up to date") because an earlier run had already written it into the workspace — incidental confirmation that agent WRITES land at the Windows path.
3. **Check 24 fails on Bret's box, and that is the honest correct result** — the automount=true drift means the isolation guarantee cannot be fully verified here; only a clean install can.

---

## BLOCKED

1. **Full isolation guarantee (check 24)** cannot pass on this machine while `automount=true`. Needs a clean install (`automount=false`) — the Azure validation path, deferred to the test-suite phase. The fix is isolation-preserving (Task 1 evidence); this is a property of the drifted host, not the fix.
2. **`nsenter` requires root** (the engine already runs mounts as root, so no change) — but a non-admin Studio service writing the ledger, plus root for nsenter, is a deployment/privilege detail to confirm at install time (carryover from Phase 1/2).

## FOR THE TEST-SUITE SPEC — verify from the CONSUMER, not the producer

The general lesson: **every security and capability claim must be verified from the consumer's point of view (the agent, the user, an outside network host), never from the producer's (the mount table, the ledger, a "success" log line).** This defect survived every prior test because they all checked the mount from a fresh `wsl` shell — the producer side — never from the agent. Other places in the codebase currently verified **producer-side only**, which should get consumer-side adversarial tests:

1. **Egress firewall** — smoke check verifies "the `clawfactory` nft chain is present" (producer). It does NOT verify, *from the agent*, that a non-allowlisted host is actually unreachable and an allowlisted one reachable. **Highest value.** An adversarial test: have the agent attempt to curl a non-allowlisted domain and confirm it fails, and an allowlisted one and confirm it succeeds.
2. **File isolation / automount** — was "/etc/wsl.conf says enabled=false" (producer). Check 24 now adds the consumer side (agent tries `/mnt/c`). Keep it; run it on a clean install.
3. **SOUL.md integrity refusal** — smoke verifies "the SHA-256 is pinned into agent.md" (producer). It does NOT verify that the agent *actually refuses every tool call* when SOUL.md is tampered (consumer). Adversarial test: mutate SOUL.md, run a turn, confirm the refusal string.
4. **Windows Firewall inbound-deny on 8787** — "the rule exists" (producer). Not "a connection from another host is actually refused" (consumer).
5. **Spend governor turn-gate** — smoke verifies `Test-TurnAllowed` returns `blocked` (producer). It does NOT verify that a *real turn is actually prevented from executing* at cap=0 (consumer).
6. **clawuser non-privilege / tool denylist** — verified by group membership + agent.md text (producer). Not by "the agent tries `sudo`/`shell`/`rm` and is refused" (consumer).
7. **Spend meter accuracy** — "usage-cost returns numbers" (producer), never reconciled against real provider billing (consumer).

Items 1, 3, and 5 are the strongest adversarial-test candidates: each is a security/capability guarantee currently proven only by a producer-side artifact.
