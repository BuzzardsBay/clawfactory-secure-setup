## THE ONE BLOCKER + THE EXACT FIX (this is the next job)

**File:** `setup.ps1`, `Step-PreinstallGatewayRuntime`, the `$gatewayInstall` bash here-string
(~line 1929 start) and the PowerShell throw (~line 2017).

**Verbatim root cause (instrumented run cfv-0716q):**
```
[gateway-install] openclaw gateway install --force --port 8787
Installed systemd service: /home/clawuser/.config/systemd/user/openclaw-gateway.service   <- unit CREATED
[gateway-install] systemctl --user daemon-reload / enable / restart
[gateway-install] Gateway service active (attempt 1)                                       <- gateway UP
[wsl:clawuser err] tee: /tmp/openclaw-install.log: Permission denied  (x3)                  <- only error
[wsl:clawuser exit] 1                                                                        <- false-fail exit
[ERROR] gateway install failed (exit=1): '...' did not create the unit ...                  <- but it DID
```

`/tmp/openclaw-install.log` is **root-owned**; the block runs as **clawuser** → the three
`systemctl … 2>&1 | tee -a "$LOG"` fail "Permission denied" → block exits 1 → false failure.

**The fix (do both; either likely suffices). Do NOT touch the ownership fix or the
unit-existence hard gate — both PROVEN working.**
1. **Drop the redundant `tee -a "$LOG"`** from the three systemctl lines (~1985/1988/1991).
   `Invoke-WslBash` already captures every `[wsl:clawuser out]` line into
   `C:\ProgramData\ClawFactory\install.log`, so teeing to the root-owned `/tmp/openclaw-install.log`
   is redundant *and* is what fails. (Alt: pre-create that log clawuser-writable, as the
   v1.0.11/13 lineage did — but dropping the redundant tee is cleaner.)
2. **Gate on the invariant, not the block exit (lesson L11):** in the PowerShell after the
   block, if `$rcGateway -ne 0`, do **not** immediately throw — verify the unit file exists
   (`Invoke-WslBash 'test -f …/openclaw-gateway.service'`) and/or let the `/status` poll
   (~2020-2050, the health authority) decide. Restore v1.0.38 *WARN-not-throw* semantics for a
   non-zero `$rcGateway` **when the unit exists**; keep the throw **only** for a genuinely
   missing unit (`exit 90` = ownership guard tripped). Do NOT tighten the `/status` poll.

Then: bump `MyAppVersion` → `1.0.41` (in `ClawFactory-Secure-Setup.iss`), commit (explicit

## Key technical context

**The harness (`scripts/azure-validate.ps1`)** — hardened over many cycles; do not regress:
- `Invoke-Rc` funnels every `az vm run-command` through one path: **`--scripts "@file"`**
  (because `az` on Windows is `az.cmd`, so cmd.exe re-parses args — L7) and **`--query
  "value[].message"`** to read BOTH stdout+stderr. Never inline a multi-line script (L2).
- **No stream redirect** on the harness invocation (`*>&1`/`2>&1`) — an `az` WARNING would
  become fatal under EAP=Stop (L5); and check `$LASTEXITCODE` explicitly because a failed `az`
  otherwise passes silently (L6).
- **Teardown** deletes every child by explicit name (child resources get deterministic names
  at create), proves with an **unfiltered** listing (L3), settles before asserting orphans,
  and **de-registers from the sweep list** (`validation-runs/ACTIVE_VMS.txt`) — which survives a
  killed harness (a killed process can't run `finally`; `scripts/azure-sweep.ps1` cleans strays).
- **Guards:** agent-Ready gate, and **terminal-`ProvisioningState/failed` abort** (a9c542b) so a
  doomed VM aborts in ms instead of hanging the stage 20 min.
- **Task H (deactivate-on-teardown):** captures the installer's exact `machine_id` = Windows
  `MachineGuid` (`HKLM\SOFTWARE\Microsoft\Cryptography\MachineGuid`) pre-install, and after VM
  delete POSTs `https://api.clawfactory.app/deactivate {key, machine_id, product:"clawfactory"}`
  to free the license slot. A failed deactivate is a logged warning, not a teardown failure.

**The probe (`scripts/probe-v1039-validation.ps1`)** — runs ON the VM as clawadmin (never
run-command, which is SYSTEM and can't use WSL). Task 2 is a hard gate (halts on fail). Task 4
is the headline: consumer-side, every claim from the **agent's own output** (`AgentSay` drives
`openclaw agent --agent main --message …` as clawuser). Bugs fixed: `--cd /` (automount=false
makes `wsl.exe` spew "Failed to translate" on the Windows CWD), robust 2.4 ownership parse, and
full gateway-section + `[wsl:clawuser exit]` capture. `adversarial-suite.ps1` is staged via
`-ExtraFiles` and run from the install dir so its `resources\` deps resolve.

**License API (product's own, api.clawfactory.app):** `/activate` and `/deactivate`, both JSON
`{key, machine_id, product}`. `machine_id` = MachineGuid; `product` = `clawfactory`;
`/LICENSE=CF-TEST-TEST-TEST-TEST` is the validation license the API accepts. The installer
activates at Inno `InitializeWizard` (before setup.ps1). Cap is 10 machines; every VM consumes a
slot — hence Task H. Success signal for the install is `INSTALLER_DONE=success` from
`install-result.txt` / the wrapper's `INSTALLER_DONE.txt`, **never** `setup.exe`'s exit (Inno
doesn't propagate the `[Run]` child exit code).

**The provisioning lottery (INFRA, not product):** the baseline image
`clawfactory-win11-baseline-v2` intermittently hits terminal `OSProvisioningTimedOut` in
westus2 (several bad draws on 2026-07-16). The guard aborts these fast; just retry a fresh name.
`clawfactoryvalc467` storage + `bake-vmVNET` + the two baseline images are the only reusable RG
items; nothing else should ever remain after a run.
