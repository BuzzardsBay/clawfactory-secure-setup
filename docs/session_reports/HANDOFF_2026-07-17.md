## Key technical context (condensed — full detail in prior close-outs)

- **`az` on Windows is `az.cmd`** → cmd.exe re-parses args. The harness funnels every
  `run-command` through `--scripts "@file"` + paren-free `--query "value[].message"` (reads BOTH
  stdout+stderr). Never inline a multi-line script; never `*>&1` the harness under EAP=Stop; check
  `$LASTEXITCODE` explicitly. (Lessons L2/L3/L5/L6/L7.)
- **The probe runs ON the VM as clawadmin** (WSL can't run as SYSTEM, so not via run-command
  directly). Every headline claim is consumer-side — `AgentSay` drives `openclaw agent --agent
  main --message …` as clawuser and reads the **agent's own output**, never a config/mount table.
- **Grants:** `Grant-Workspace` maps a Windows folder to `/workspaces/<grant-id>` (9p). `C:\cfv\
  granted` → deterministic id `granted-ba622b4f`. A positive control MUST open the grant mount
  (`/workspaces/<grant-id>/…`), not the home workspace (that was the cfv-0717f false-fail — L19).
- **Spend meter:** the turn-gate reads `openclaw gateway usage-cost --json --days 400`; that WS
  query is cold for ~1–2 min after the final port-move restart even though `/status` is 200 — the
  root of the first-turn blanks. v1.0.45 primes it at end-of-install + retries in the gate.
- **chatCompletions proxy:** root-owned proxy owns `:8787`; the real gateway is on private
  `127.0.0.1:8788`. The gate re-enters the proxy, so it's async. The CLI speaks **WebSocket** (not
  HTTP) — a trap when testing. The gateway unit hardcodes `--port`.
- **License API** (`api.clawfactory.app`): `/activate` + `/deactivate`, JSON `{key, machine_id,
  product:"clawfactory"}`; `machine_id` = Windows `MachineGuid`. Validation license
  `CF-TEST-TEST-TEST-TEST`; cap 10 machines (hence Task H).
- **OpenClaw API key** lives in `~/.openclaw/auth-profiles.json` (global + per-agent, mode 600),
  NOT env/cred-manager. Rotating = rewrite those files + restart gateway.
