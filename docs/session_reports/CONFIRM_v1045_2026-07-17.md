## What shipped in v1.0.45 (the meter fix — PART A)

The first agent turn(s) after a fresh install were fail-safe **blocked** because the
turn-gate reads spend via `openclaw gateway usage-cost --json --days 400`, and that
WebSocket query returns **empty while the gateway is cold** → `spend_meter_unknown` →
block. That is correct fail-*closed* behaviour, but it made the very first turn (and the
4.2 positive control that runs right after install) look broken. Two changes, both
fail-safe-preserving:

| File | Change |
|---|---|
| `resources/clawfactory-turn-gate.sh` | wrap the `usage-cost` read in a bounded retry (10× / ~10s); still emits `spend_meter_unknown` and returns 1 if it never warms — the fail-closed contract is untouched |
| `setup.ps1` | after the final health gate, **prime the meter** as `clawuser` (non-fatal, ~120s budget) so the meter is warm before the customer's first turn |
| `ClawFactory-Secure-Setup.iss` | version → `1.0.45` |

Probe-only fix (validation harness, no product change) `b14f7bc`: the 4.2 positive control
now points at the **granted mount** (`/workspaces/<grant-id>/project-note.txt`) instead of
the home workspace, and warms with a throwaway-turn loop before measuring. The `cfv-0717f`
"file does not exist" FAIL was this probe bug (reading the home dir), not a product defect.

Everything explicitly out of scope was left untouched: the install path, the restart
class, the firewall, SOUL.md protection itself, and the Door-2 full-path `.mjs` bypass.
